## 实现与实验环境

适配使用原生 `{ id, server }` 入口，通过 `config.skills.paths` 注册共享技能，
通过 system hook 提供父子会话的安装路径和原生操作说明。调度提醒从接收会话自己的
原生历史重建，存储消息、命令文本和宿主权限保持原样。入口移动到单层
`.opencode/plugins/veripower.js`，同时服务本地自动发现和包的 `./server` 导出。
移除了原先仅供 v2 技能注册使用的 JavaScript YAML 解析依赖。

实验使用本机 `/home/mhc/.opencode/bin/opencode`，版本 `1.19.0`；Node.js `24.15.0`，
Python `3.12`。打包安装使用 `npm pack` 的实际产物。原生服务器使用独立的 XDG 目录、
`OPENCODE_CONFIG_DIR` 和 `OPENCODE_TEST_HOME`，开启原生后台子 agent 能力。
真实模型会话使用现有凭据访问 DeepSeek API，请求模型为 `deepseek-flash`；模型响应
未经脚本预设。凭据和原始会话日志不进入仓库。

真实模型实验的适配代码 SHA256：
`d1a4041e9f6eb02ee0b74ca2be1f78733a4e036aec4cc4ab3d17568e94d5fe12`。
实验初次打包后修改了安装说明和测试辅助代码；适配运行代码保持这个摘要。

## 自动与脚本化原生验证

```bash
npm ci --ignore-scripts
python -m pytest -q tests/unit/ tests/contracts/
VERIPOWER_OPENCODE_TESTS=1 python -m pytest -q tests/unit/test_platform_runtime.py -k opencode
pre-commit run --all-files
```

共享单元与契约检查为 **1164 passed，31 skipped**。OpenCode 原生检查为
**5 passed**。语法、diff 空白检查及 pre-commit 均通过。

| 原生场景 | 观察结果 |
|---|---|
| 允许命令 | 打包安装后发现 12 个技能；独立子会话加载当前技能，正常完成后通知父会话；调度提醒跨任务启动保留，并在下一次可识别的 kernel 调用后消失 |
| 拒绝命令 | `bash: deny` 下测试命令没有执行，适配没有放开权限 |
| 拒绝审批 | 宿主审批请求被拒绝后，命令没有执行；OpenCode 停止该模型轮次 |
| 取消子会话 | 宿主记录 `MessageAbortedError` 且确认执行器退出后，显式恢复父会话成功，原生适配说明仍在 |
| 关闭后台能力 | 工具 schema 不提供后台参数，强行调用报告缺少后台开关，未启动子会话 |

正常场景还验证了工具说明只进入 system 上下文，用户消息不被改写；原生持久历史中没有
注入的适配说明或调度提醒。单元检查覆盖配置幂等性、权限保留、会话隔离、恢复后的
提醒重建、引号路径、错误输出及后续 kernel 调用。

取消实验确认：v1.19.0 显式取消子会话后不会发送正常完成通知。相应使用方式是通过宿主
确认取消和退出，再恢复父会话收集。安装说明已记录这一行为，没有另建后台任务管理器。

调度提醒按 bash 记录中的字面 `kernel.py` 调用识别；适配不展开 shell 变量或别名。
共享 design-flow 仍负责执行调度循环，提醒不代替 kernel 的调度决定。

## 真实模型的规格交付与独立审查

输入是一个 4 位模 16 计数器：单一 10 ns 时钟，异步低有效复位，en 为高时递增，
否则保持，15 后回到 0。任务仅要求完成并收集 specification，不执行后续阶段或 signoff。
模型可以在原始意图内作普通工程决定，独立后台 reviewer 使用自包含任务和文件路径。

观察到的完整过程：

1. 主会话加载当前安装的 `design-flow` 和 `specification`，经真实 kernel dispatch 建立 run 1。
2. 编写 design、需求账本、接口、时钟、检查提示等工件，通过当前技能 CLI 的账本、
   交叉引用和约束生成检查。
3. 启动独立后台 reviewer，父会话结束当前响应并等待原生完成通知。
4. reviewer 报告一项非阻塞的需求编号引用错误；主会话修正设计文档及决定记录。
5. 主会话通过真实 specification CLI finalize，并由 kernel 收集和发布工件。

独立核对 `events.jsonl`，仅有 specification run 1 的 dispatch 与 pass outcome；
`kernel.py status` 为 `specification: valid`，其余阶段 missing，`signed_off: false`。
这是实际规格阶段的交付与收集验证，不是完整 IC 流程或计数器 RTL 功能验证。

工件在 `/tmp/veripower-oc119-live/counter4/Design/specification/`，包括
`result.json`、`spec-review/findings/specification-review.md` 和
`spec-review/decisions.md`。原始输入在同模块的 `intent/brainstorm.md`。

## 真实模型的并发与权限实验

另一个父会话启动两个独立后台检查任务：一个检查权限、命令和父子上下文边界，另一个
检查安装后的技能路径、kernel 及阶段 CLI 入口。两个子会话的实际执行区间重叠约
42 秒；父会话先等待，再分别收到两份原生完成通知，读取报告并汇总。

安装位置的 12 个技能目录、kernel 及其 7 个子命令、9 个阶段 CLI 的帮助入口均可解析。
这些检查任务没有伪造阶段结果，也没有写 kernel 事件。
报告在 `/tmp/veripower-oc119-live/concurrency/`。

在独立设置 `bash: deny` 的真实模型会话中，模型加载 `design-flow` 后报告 kernel 状态
查询被宿主策略阻止，没有执行命令、修改权限或用读取结果文件替代 kernel 查询。

并发检查发现了两个问题：首次实验包的 README 仍描述 v2 接口，以及单元测试辅助代码
使用 URL 的编码 pathname 比较 npm `@file:` 缓存目录。安装说明已改为 v1；测试辅助代码
改用 `fileURLToPath`。适配运行代码没有这项 URL 比较错误。

## 插件安装与生命周期

更新实验使用不同的产物来源；没有把重新启动等同于刷新同一 Git 分支名的包缓存。

## 真实环境检查

环境模型会话加载安装包中的 `env-precheck`，实际执行工具与许可证检查。以下产物已另行
检查其非空内容及对应标记，不仅依赖模型的最终描述：

| 能力 | 实测版本与结果 |
|---|---|
| DC 综合 | L-2016.03-SP1，`compile_ultra` 生成映射网表和 DDC |
| PT 时序 | M-2016.12-SP1，`report_timing` 给出实际路径 |
| PT-PX 功耗 | M-2016.12-SP1，生成 `report_power` 表 |
| VCS 与 UVM | L-2016.06、UVM 1.1，编译运行并输出 `UVM_SMOKE_DONE` |
| 覆盖率 | VCS `-cm` 与 URG L-2016.06，生成 dashboard |
| 波形 | Verdi/FSDB L-2016.06，产生 FSDB 并查询到时序值 |
| Lint | SpyGlass vL-2016.06，lint 目标产生非空报告 |
| CDC | SpyGlass vL-2016.06，setup、setup_check、verify_struct 三个目标均产生非空报告 |

这些是环境能力 smoke，不构成完整设计的功能、时序或功耗验收。详细输入、命令、
错误及报告在 `/tmp/veripower-oc119-live/environment/`。

实测发现 EDA 包装器的容器只挂载 `/home/mhc`：从宿主 `/tmp` 工作目录直接调用会因路径
不可见而失败。DC smoke 最初在技能默认的 `/home/mhc/.vp-env-precheck/` 执行，偏离了
原始任务指定的写入范围；通过追加范围澄清纠正后，后续宿主工件进入指定目录，其余
工具输入暂存到容器内并回收结果。这些 smoke 建立工具能力，没有把 `/tmp` 中的模块
描述成可以原地运行完整 EDA 流程。VCS 另验证了部署已有的 `proc_fix.so` 与 `-full64`。
未修改部署配置或安装软件，原始目录没有被删除。
